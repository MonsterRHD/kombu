Prompt-Rubric 对齐审计：逐条核对冻结 Rubric 与原始中文 Prompt 的场景、目标、失败边界、兼容描述；以下每项引用原 Prompt 已明确的可观察目标。未发现新增接口、文件、错误码、部署或测试夹具门槛。
P-R 对齐表：
R1 → Prompt 场景/目标原文“修正该传输的磁盘协议”：发布通过同一文件系统的临时写入、文件同步和原子公布完成，消费者不会读到截断或未完成消息。
R2 → Prompt 场景/目标原文“修正该传输的磁盘协议”：消费者原子取得带期限的领取租约，多进程竞争同一消息时只有一个有效领取者。
R3 → Prompt 场景/目标原文“修正该传输的磁盘协议”：成功确认后消息才删除或进入 processed，确认失败保留可恢复状态且不会假报成功。
R4 → Prompt 场景/目标原文“修正该传输的磁盘协议”：reject(requeue=True) 将原消息标识重新公布，reject(requeue=False) 按既有丢弃语义最终化。
R5 → Prompt 场景/目标原文“修正该传输的磁盘协议”：进程在发布或领取任一点崩溃后，扫描能隔离临时文件并回收过期租约，不永久丢失已公布消息。
R6 → Prompt 场景/目标原文“修正该传输的磁盘协议”：输入、输出和 processed 目录跨设备且无法原子移动时启动即明确报错。
R7 → Prompt 场景/目标原文“现有文件命名兼容读取，队列大小、清空和 processed 模式应只统计已公布或已确认的消息”：现有最终文件命名仍可消费，新消息的稳定标识在重排和恢复后保持不变。
R8 → Prompt 场景/目标原文“现有文件命名兼容读取，队列大小、清空和 processed 模式应只统计已公布或已确认的消息”：queue size、purge 和 processed 模式只统计相应已公布或已确认消息，不把临时/租约文件计入。
